## v0.2.0 からの変更

### 日本語の名前
- 設定メニューのディスクのイメージの一覧で、日本語のファイル名を CGROM (X68000 の文字のフォントの ROM) の字で出す。CGROM.DAT がなければ、全角の字は四角、半角カタカナは `?` になる。一覧に出るのは、名前が拡張子を含めて 95 バイトまでのもの (UTF-8 の全角は 1 字 3 バイトなので、全角だけの名前なら、`.XDF` のような 4 バイトの拡張子を除いて 30 字まで)。日本語の名前は英数字の名前のあとに並べる。
- ベアメタル版は SD カードのファイル名を UTF-8 で扱う。長い名前のない 8.3 の名前は Shift_JIS として読む。`pix68k.cfg` の `fd0=` などに日本語の名前を書くときは、`pix68k.cfg` を UTF-8 で書く。
- v0.2.0 までのベアメタル版で、HTTP の `PUT /files` から日本語の名前で置いたファイルは、化けた名前で SD カードに書かれている。この版では名前が化けて見えるので、消してから置き直す。
- 起動の組み合わせのメニューで、`pix68k-<名前>.cfg` の 1 行目に書いた題を、UTF-8 でも Shift_JIS でも読む。1 行目が正しい UTF-8 なら UTF-8、そうでなければ Shift_JIS として読む (UTF-8 の BOM があれば UTF-8)。半角カタカナだけの題で、バイトの並びがたまたま正しい UTF-8 にもなるもの (`ﾂｰ` = 0xC2 0xB0 など) は化ける。全角の字を混ぜるか、UTF-8 で書けば正しく出る。

### ゲームパッド
- Start と Select を同時に押すと、X68000 をリセットする (設定メニューの Reset と同じ)。押し続けてもリセットは 1 回だけで、両方を離すまで次のリセットはしない。Switch Pro コントローラは + と -。ホスト版 (SDL2) は Start と Back。
- Home か、Select を押しながら十字キーの上で、設定メニューを開く / 閉じる。メニューの中では、十字キーとスティックで選び、A / X で決め、B / Y で戻る / 閉じる。Select と上は、Select を先に押す。ホスト版は Guide か、Back を押しながら上。
- HORI の HORIPAD S (VID:PID 0f0d:00c1) に対応した。Circle (ベアメタル版の USB の処理に使っているライブラリ) がボタンの配置を知らないゲームパッドでも、pix68k の表に VID:PID があれば、ボタンを並べ直して同じように扱う。今の表にあるのは HORIPAD S だけ。
- リセットと設定メニューのボタンは、ベアメタル版では Circle が配置を知っているゲームパッドか、上の表にあるゲームパッドで使える。
- `pad_log=on` を `pix68k.cfg` に書くと、ゲームパッドのボタンとハット (十字キー) の生の値を、変わるたびにログに出す。表にないゲームパッドのボタンの並びを調べるためのもの。ログを USB の割り込みの中で書くので、調べ終えたら `off` に戻す。ゲームパッドをつないだときのログにも、VID:PID を出すようにした (例: `gamepad attached (upad1, 0f0d:00c1, joystick 1, layout HORIPAD S)`)。

### 画面
- スプライトどうしの重なり順を直した。これまでは優先度 (スプライトのスクロールレジスタの第 4 ワードの下位 2 ビット) ごとに重ねていたので、優先度 3 で番号の大きいスプライトが、優先度 2 で番号の小さいスプライトの手前に出ていた。今は、優先度によらず番号の小さいスプライトを手前にし、優先度は BG の前に出すか後ろに出すかだけに使う。グラディウス II のサウンドモードの画面で、ボタンの枠がラベルの最後の字を隠していたのが直った。公開リポジトリの PR #2 で x68k-xvi さんが直してくれたものを取り込んだ。ありがとうございます。
- Raspberry Pi 4 / 5 のベアメタル版で、TS-6BGA (X68000 用のグラフィックボード) 互換のフレームバッファを 2 つめの HDMI に出せるようにした。`cmdline.txt` に `pix68k_ts6bga=1` (VRAM を `$EE0000` に置く) か `pix68k_ts6bga=2` (`$EF0000`) を足し、両方の HDMI にディスプレイをつないで起動する。X68000 では、GORRY 氏の TGA_005B に入っている `TS6BGAG.X` を組み込んで使う (リリースの zip には入れていない)。HTTP の `GET /ts6bga.ppm` と `GET /screen2.ppm` で、TS-6BGA の VRAM と 2 つめの HDMI の画面を取れる。詳しくは `docs/ts6bga.md`。

### 音
- MIDI の音源を鳴らしたとき、音の大きさをログに出す (`sound level: peak ... before MIDI, MIDI peak ... (of 32767), ... frame(s) clipped after the mix`)。MIDI の音源を足す前の最大、MIDI の音源の最大、足して 16 ビットの範囲を超えたので上限と下限で止めたフレームの数を出す。MT-32 で音が割れるという報告を調べるためのもの (原因はまだ分かっていない)。

### RetroArch のコア (開発中)
- RetroArch (libretro) のコア `pix68k_libretro` をソースからビルドできるようにした。68000、メモリ 2MB (12MB も選べる)、16MHz (10MHz も選べる)、FPU ボードなし。XDF / DIM / D88 の FD (複数枚は `.m3u`) と SASI の HDF から起動する。ステートの保存と復元もできる。RetroPie 用のモジュール (`retropie/`) と、PS Vita 用のビルド (`libretro/vita/`) もある。コアはリリースの zip には入っていない。ビルドの手順は README の「RetroArch / libretro」にある。

## Changes since v0.2.0 (English)

### Japanese file names
- The disk image list in the settings menu now shows Japanese file names with glyphs from CGROM (the X68000 character font ROM). Without CGROM.DAT, full-width characters are shown as boxes and half-width katakana as `?`. Names up to 95 bytes including the extension are listed (a full-width character is 3 bytes in UTF-8, so a name of only full-width characters can have up to 30 characters plus a 4-byte extension such as `.XDF`). Japanese names are listed after alphanumeric names.
- The bare-metal build handles SD card file names as UTF-8; old 8.3 names without a long name are read as Shift_JIS. To use Japanese names in `pix68k.cfg` (e.g. `fd0=`), write `pix68k.cfg` in UTF-8.
- Files uploaded with Japanese names through HTTP `PUT /files` by the bare-metal build of v0.2.0 or earlier were written to the SD card with garbled names and look garbled in this version. Delete them and upload again.
- The boot profile menu reads the title on the first line of `pix68k-<name>.cfg` as UTF-8 or Shift_JIS: UTF-8 if the line is valid UTF-8 (or starts with a UTF-8 BOM), otherwise Shift_JIS. A title of only half-width katakana whose bytes happen to be valid UTF-8 (e.g. `ﾂｰ` = 0xC2 0xB0) is garbled; add a full-width character or write it in UTF-8.

### Gamepads
- Pressing Start and Select together resets the X68000 (same as Reset in the settings menu). Holding them resets only once; both must be released before the next reset. On a Switch Pro Controller use + and -. In the host (SDL2) build, Start and Back.
- Home, or Up while holding Select, opens and closes the settings menu. In the menu, use the D-pad or sticks to move, A / X to select, B / Y to go back or close. Press Select before Up. In the host build, Guide, or Up while holding Back.
- Added support for the HORI HORIPAD S (VID:PID 0f0d:00c1). Gamepads whose button layout Circle (the library the bare-metal build uses for USB) does not know are remapped when their VID:PID is in pix68k's table. The table currently has only the HORIPAD S.
- On the bare-metal build, the reset and menu buttons work with gamepads whose layout Circle knows or that are in the table above.
- `pad_log=on` in `pix68k.cfg` logs the raw button and hat values of gamepads whenever they change, to find the button order of gamepads not in the table. The log is written in the USB interrupt, so set it back to `off` when done. The log line when a gamepad is connected now also shows its VID:PID (e.g. `gamepad attached (upad1, 0f0d:00c1, joystick 1, layout HORIPAD S)`).

### Display
- Fixed the order of overlapping sprites. Sprites used to be layered by priority (the low 2 bits of the fourth word of the sprite scroll register), so a higher-numbered sprite with priority 3 appeared in front of a lower-numbered sprite with priority 2. Now the lower-numbered sprite is always in front, and priority only decides whether the sprite is in front of or behind the BG. This fixes the button frames hiding the last character of the labels on the Gradius II sound mode screen. The fix comes from PR #2 by x68k-xvi in the public repository. Thank you.
- On the Raspberry Pi 4 / 5 bare-metal build, a frame buffer compatible with the TS-6BGA (a graphics board for the X68000) can be shown on the second HDMI output. Add `pix68k_ts6bga=1` (VRAM at `$EE0000`) or `pix68k_ts6bga=2` (`$EF0000`) to `cmdline.txt` and boot with displays connected to both HDMI ports. On the X68000, load `TS6BGAG.X` from GORRY's TGA_005B (not included in the zip). HTTP `GET /ts6bga.ppm` and `GET /screen2.ppm` return the TS-6BGA VRAM and the second HDMI screen. See `docs/ts6bga.md`.

### Sound
- When a MIDI synth plays, the log shows sound levels (`sound level: peak ... before MIDI, MIDI peak ... (of 32767), ... frame(s) clipped after the mix`): the peak before adding the MIDI synth, the MIDI synth's peak, and the number of frames clipped at the 16-bit limits. This is for investigating reports of distorted MT-32 sound (the cause is not found yet).

### RetroArch core (in development)
- A RetroArch (libretro) core, `pix68k_libretro`, can be built from source: 68000, 2MB of memory (12MB selectable), 16MHz (10MHz selectable), no FPU board. It boots from XDF / DIM / D88 floppy images (several disks with `.m3u`) and SASI HDF images, and supports save states. There is also a RetroPie module (`retropie/`) and a PS Vita build (`libretro/vita/`). The core is not in the zip; see "RetroArch / libretro" in the README for build steps.
