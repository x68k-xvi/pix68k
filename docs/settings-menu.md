# 設定メニューとステート

設定メニューの開き方と項目、ステートの保存と読み込み、ホスト版のメニュー。

## 設定メニュー

PC につながずに、ディスクの入れ替えや設定の変更ができる。X68000 の画面の上にメニューを重ねて出す。

- 開く / 閉じるキー: USB キーボードの Scroll Lock、Application (右 Windows キーの隣のメニューのキー)、Menu。Raspberry Pi 400 ではラズベリーのキー + M。
  どれも X68000 のキーに割り当てていないので、メニューのために使えなくなる X68000 のキーはない (F12 は X68000 の XF2 なので使わない。ホスト版だけは F12 でも開く)
- 操作: ↑↓ で項目を選ぶ、←→ で値を変える、Enter で決める、Esc (か Backspace) で戻る / 閉じる。↑↓←→ は押し続けると繰り返す
- ゲームパッド: Home (PS ボタン、Xbox のガイドボタン、Switch Pro の Home) か、Select を押しながら上で開く / 閉じる (Home のないゲームパッド向け。
  Switch Pro は - か Capture を押しながら上。Start + Select はリセットなので使わない)。開けるのは、ベアメタル版では Circle が配置を知っているゲームパッドか、pix68k の表にあるゲームパッド (今は HORIPAD S だけ。[baremetal.md](baremetal.md))。
  メニューの中では、十字キー (ハット、アナログスティックも) が ↑↓←→、A / X が Enter、B / Y が Esc になる (キーボードのメニューのキーに置き換えて渡す)。
  上下左右は押し続けると繰り返す。Select + 上は Select を先に押す (上を先に押すと、開くまでの間だけ上が X68000 に届く)。配置の分からないゲームパッドでも、キーボードで開いたメニューの中ではハット、軸、ボタン 1 / 2 で操作できる。
  ホスト版は SDL のゲームコントローラの Guide と Back で同じように動く
- 項目:
  - FD0 / FD1: `/pix68k/` にあるフロッピーディスクのイメージ (`.xdf`、`.dim`、`.d88`、`.hdm`、`.2hd`) の一覧から選ぶと、すぐに入れ替える。一覧の先頭の [Eject] で取り出す。読めないイメージを選んだときは、入っているディスクはそのまま
  - HD0 (SASI): `.hdf` の一覧から選ぶ。次の起動から
  - CD-ROM: `.iso` と `.cue` の一覧から選ぶ。CD-ROM 装置をつないで起動していれば、すぐに媒体を入れ替える ((none) で取り出す。読めないイメージを選んだときは、入っている媒体はそのまま。ベアメタル版で、前の媒体を外したあとにメモリが足りなかったときは、装置は空になり、そう出す)。つないでいなければ次の起動から (外付け SCSI ボードか、X68030 / 060turbo の内蔵 SCSI が要る)
  - SCSI board (68000 のとき): 外付け SCSI ボード (`scsi_ex`)。次の起動から
  - SC0〜SC6: SCSI のハードディスクのイメージを `.hds` の一覧から選ぶ。次の起動から。CD-ROM と同じ ID ならそう出す (CD-ROM を使う)
  - CPU、Clock (68000 のとき)、RAM、High memory (68030 のとき)、Local memory (68060 のとき)、Max speed: 次の起動から。動いている値と違う項目には「*」を付ける
  - Boards: Enter で拡張ボードのページに入る (Esc か Back で戻る)。主のページには、つなぐボードの名前を出す
    - FPU board、Mercury Unit、Neptune-X、MIDI board: 拡張ボード (`fpu_board`、`mercury`、`neptune`、`midi`) の on / off (FPU board は off、on、2)。次の起動から。どの CPU でも出す
    - MIDI out (MIDI board が on のとき): MIDI の行き先 (`midi_out`、SoundFont / UART / none / MT-32 / SC-55)。次の起動から。その環境で使えないもの
      (Raspberry Pi 3 のビルドの SC-55、`--midi-dump` を付けていないホスト版の UART) は選べない。SoundFont や ROM のファイル名 (`midi_sf2` など)、
      Neptune-X の MAC アドレスと送受信の先はメニューでは変えられないので、pix68k.cfg に書く (ファイル名を書いていない行き先を選ぶと、要るキーを出す)
  - Display: Enter で画面の出し方のページに入る (Esc か Back で戻る)。主のページには「aspect + scanline,curve」のようにまとめて出す。
    どの項目も変えるとすぐに反映する (保存するには Save settings)
    - Scale: 画面の拡大の仕方 (`video_scale`、off / integer / aspect / full)
    - Scanlines、Curve、Mask: ブラウン管のように見せる効果 (`video_filter` の `scanline`、`curve`、`mask`) の on / off。自由に組み合わせられる。
      その機種で選べない組み合わせ (Raspberry Pi 3 の Curve など) は選ばない。Scale はその値を飛ばし、効果は変えずに
      「not available on this machine」と出す (README の「画面の出し方」)
    - Bezel: モニタの枠 (`video_filter` の `cz-600de` / `cz-600db`)。off、cz-600de (グレー)、cz-600db (黒) の順に替える。ベアメタル版だけに出す。
      初めて選んだときに起動したドライブの `/pix68k/bezel-cz-600de.bin` などを読み、読めなければ選ばない。枠があるときは、主のページの Display は
      「cz-600de + scanline,curve,mask」のように、拡大の代わりに枠の名前を出す (枠はガラスの部分に写し、Scale を使わない)
  - OSD: 画面の右上の数字 (`osd`、off / on / fps)。ベアメタル版は余白が足りなければ on でも X68000 の画面に重ねる (ホスト版は fps のときだけ重ねる)。メニューを開いている間は出さず、on か fps にしてメニューを閉じると 1〜2 秒で出る (数え直すため)。保存するには Save settings を選ぶ
  - State slot、Save state、Load state: ステートの保存と読み込み (下を参照)
  - Reset: X68000 をリセットする (電源を入れ直したときと同じ)
  - Save settings: pix68k.cfg に書く。変えた項目の行だけを書き換え (なければ最後に足す)、ほかの行、注釈、知らないキー、改行の形 (CRLF) はそのまま残す。
    書いている途中で電源が切れても前の設定が残るよう、`pix68k.new` に書いてから `pix68k.cfg` と置き換える
  - Restart: 設定を pix68k.cfg に書いてから再起動する (SRAM も書く)。「*」の付いた項目はこれで反映する
- メニューを開いている間は X68000 を止める (CPU も周辺機器も、音も止まる)。閉じると続きから動く。止めていた時間は取り戻さないので、X68000 の時計は止めていた分だけ遅れる。
  止めるのは、ディスクの入れ替えやステートの保存をフレームの途中でしないため
- 開いている間、キー、マウス、ゲームパッドは X68000 に送らない。開くときに押しているキーは X68000 には離したことにし、閉じるときに押していたキー
  (閉じるのに押した Enter など) は、一度離すまで X68000 に送らない。ゲームパッドも同じで、閉じるときに押していたボタンと方向 (閉じるのに押した A など) は、
  一度離すまでジョイスティックとして送らない
- 画面: コア 1 はフレームの切れ目で、コア 2 (画面の合成) とコア 3 (音の合成) が受け取った記録を処理し終えるのを待ってから止まる。
  コア 0 が最後に受け取った X68000 の画面をフレームバッファに写し、その上にメニューを描く。コア 2 の合成とフレームの受け渡しには手を入れないので、
  メニューを閉じたあともフレームは飛ばさない

ステート: X68000 の実行状態 (CPU (68000 / 68030 / 68060 と FPU)、メモリ、SRAM、画面、音、周辺機器、外付け SCSI ボード、数値演算プロセッサボード (2 枚まで)、まーきゅりーゆにっと、Neptune-X) を `/pix68k/state0.p68` から `state9.p68` に保存する
(ホスト版は `--state-dir`、既定 `~/.cache/pix68k`)。ファイルの頭に版番号 (`src/x68k/state.h` の `STATE_VERSION`) と機種の組み合わせ (CPU、メモリの容量、クロック、
IPL ROM と SCSI ROM の CRC32、拡張ボードの有無) と中身の CRC32 を置き、合わないファイルは読まない (メニューに理由を出す。X68000 は変えない)。
版 2 のファイル (拡張ボードを足す前) は、数値演算プロセッサボードもまーきゅりーゆにっともつないでいなければ読む。版 3 のファイル (大きなイメージを足す前) も読む。
ディスクのイメージの中身と、どのイメージを入れているかはステートに入れない。読み込んだときに入っているディスクをそのまま使うので、保存したときと同じディスクを入れてから読む。X68000 の時計 (RTC) も保存したときの時刻に戻る。
全部が 0 のメモリのページは 1 バイトにするので、Human68k を起動したところで約 0.5MB (4MB の機種)。メモリを使うほど大きくなる (4MB の機種で最大約 6MB の見積もり)。
版 9 から、68060 の MMU が有効な間は、表を引いた結果を覚えている TLB と ATC も入れる (空から始めると、読んだあとに同じページを使うたびに
表を引き直すので、サイクル数がずれ、PFLUSH せずに書き換えたデスクリプタが使われて、保存しなかったときと結果が変わる)。版 8 までのファイルも読む
(TLB と ATC は空から始まる)。
版 10 から、68060 のサイクル数の数え方の状態 (同時実行の相手、分岐の折りたたみ、分岐キャッシュ、命令の取り出しの位置) も入れる
(入れないと、保存したところから続けたときと、読み込んで続けたときで、サイクル数が変わる)。版 9 までのファイルも読む (空から始まる)。
版 16 で、2 枚目の数値演算プロセッサボードを入れられるようにした (2 枚目をつないでいるときだけ入る)。0 枚か 1 枚なら版 15 と同じ並びで、版 15 までのファイルも読む。
2 枚のステートは 1 枚の X68000 では読まず、その逆も読まない (ボードの組み合わせが違う)。
版 13 で、ADPCM (MSM6258) の状態の並びを変えた。版 12 までのファイルも読むが、ADPCM は「再生中か」だけを引き継ぐ
(再生の途中で保存したファイルは、波形を中心に戻して、続きのデータから再生する。止まっていたファイルは止まったまま)。
CRC が合っていても値が取りうる範囲にないファイルの扱いは、値によって 2 通りある。
- X68000 を変える前に断るもの (理由は layout does not match): 配列の添字や個数、フェーズ、0 か 1 の値、フラグと割り込みのレベル、時間の端数、
  マウスの移動量、数値演算プロセッサボードの受け渡しの長さ、OPM と ADPCM の、表の添字やシフトの数に使う値。
- 読んだうえで直すもの: MIDI ボード (FIFO の位置と個数、覚えている音源の設定を範囲に収める)、CPU のサイクル数から離れすぎた時刻 (今に合わせる)、
  SASI / SPC / FDC / 数値演算プロセッサボードの、組み合わせが合わない転送の途中の状態 (その転送を捨てる。SPC がつながっていないのに残っている
  フェーズや ACK を消す)、68060 の TLB と ATC の、戻せない項目 (捨てる)。
  CPU の時刻 (電源を入れてからのサイクル数) が上限を超えていれば、小さい値 (2^40 サイクル + 上限の半分で割った余り) に直し、時刻で持っている
  ほかの値 (ラスタ、キーボード、マウス、MIDI ボード) も同じだけ戻す。今より 2^40 サイクル (50MHz で 6 時間ぶん) 以上前の時刻でなければ、
  値どうしの差は変わらないので、続きは同じに動く。64 ビットの上限の近くでは、進める先の時刻の足し算があふれて止まるため。
  上限は、68000 が 2^62 サイクル (16MHz で 9 千年ぶん。手で作らないかぎり、超えるステートはできない)、68030 / 68060 が 2^49 サイクル
  (中では 1/12800 サイクルの単位で数えるので、64 ビットに入るのは 1.4 x 10^15 サイクルまで。2^49 サイクルは 50MHz で動かし続けて 130 日ぶんで、
  そこからあふれるまではさらに 203 日ぶんある。版 14 までのステートは 1/800 サイクルの単位で、読むときに直す)。
  ステートを読まずに続けて動かしたときも、上限を超えたら次のフレームの初めに同じ戻し方で時刻を戻す (`Machine::rebaseTime()`) ので、あふれて止まることはない。上限ちょうどのステートから動かして保存したもの (時刻は上限を超えている) も読める。今つないでいるディスクや機器と合わない転送の途中の状態も、その転送だけを捨てる
  (媒体を取り出してある CD-ROM 装置は、装置があるので、コマンドの受け取りや INQUIRY、REQUEST SENSE の応答の途中を続ける)。
確かめているのは、添字、個数、シフトの数、繰り返しの回数になる値 (MFP のプリスケーラの残り、OPM のタイマと BUSY の残り、音のサンプルの中のクロック、
時間の端数など) と、足し引きであふれる値 (音のフィルタ、マウスの移動量) で、68030 / 68060 の PC が奇数のものも断る (命令の語を偶数の前提で読むため。68000 は読むたびに確かめてアドレスエラーにする)。
ほかの CPU のレジスタとメモリの中身は確かめない。
確かめ方 (ctest の `state_test`、`sasi_test`): 68030 の MMU のレジスタ、68060 の MMU が有効で TLB と ATC に項目がある状態、SASI / FDC / ADPCM と DMAC /
MIDI ボード / 外付け SCSI ボードの動作の途中のすべての区切りで保存し、読んで続けた結果 (CPU のサイクル数とレジスタ、RAM、VRAM、画面、ディスクのイメージ、
終わりのステート) が、保存しなかったときと同じこと。途中で切れたファイル、大きさや機種の違うファイル、中身を書き換えて CRC を合わせ直したファイルを
読ませても、断ったときに X68000 が変わらず、読んだときに範囲の外を読み書きしないこと (ASan / UBSan のビルドで `state_test --corrupted` を、
`STATE_TEST_ROUNDS` で回数を増やして回す。乱数で書き換えるものと、決め打ちの組み合わせの両方)。`state_test_human68k`、`state_test_human68k_x68030`、`state_test_human68k_060turbo` (060turbo.sys を組み込んだ 060turbo) は、Human68k の起動の途中と、
起動したあとの場面 (ユーザモードの計算、グラフィックと OPM、フロッピーディスクの読み込み) の途中で保存し、4 秒ほど動かして比べる。

ホスト版: `--config FILE` で設定ファイルを読むと、メニューの「Save settings」はそのファイルに書く。ディスクのイメージの一覧は `--image-dir` (既定は設定ファイルの
ディレクトリ、なければ `~/.cache/pix68k/disk`) から作る。「Restart」は設定ファイルに書かずに、選んだ設定で X68000 を作り直す。
メニューを開いている間は画面を 768x512 に引き伸ばしてメニューを重ねる。`--press menu,down,enter --press-after 600` のように、試験用にキーを押せる。
