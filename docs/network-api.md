# ネットワークの口 (HTTP と syslog)

Pi の有線 LAN で動かす HTTP の口 (ファイルの読み書き、再起動、ログ、画面、キー入力、メッセージ) と syslog。

文中の #番号 は、開発用の非公開リポジトリの issue と PR の番号。

SD カードを抜かずに、離れた場所にある pix68k 専用の Pi のカーネルや設定を入れ替え、ログと画面を見るための口。Pi の有線の Ethernet
(Raspberry Pi 3 Model B+ は USB の先の LAN7800、Raspberry Pi 3 Model B は LAN9514、Raspberry Pi 4 / Raspberry Pi 400 は GENET、Raspberry Pi 5 は RP1 の MACB) で Circle の TCP/IP を動かし、
HTTP (80 番) のサーバと syslog の送信を行う。既定では動かさない (`net=off`)。Wi-Fi は使えない。

`pix68k.cfg` の項目 (同じ名前に `pix68k_` を付けて `cmdline.txt` に書くと、そちらを使う。例: `pix68k_net=on`):

| 項目 | 内容 |
| --- | --- |
| `net=on` | ネットワークの口を動かす (既定は `off`) |
| `net_ip=192.168.1.50/24` | 固定のアドレス (書かなければ DHCP)。`net_gw=` でゲートウェイ、`net_dns=` で DNS サーバ |
| `net_name=x68000` | DHCP で送るホスト名 (既定は `pix68k`)。ルータがこの名前を DNS に載せれば、`http://x68000/` で届く |
| `net_allow=192.168.1.0/24,10.0.0.5` | 使ってよい相手のアドレス (CIDR か 1 つのアドレスをカンマで並べる)。書けば、ほかのアドレスからは読むこともできない |
| `net_token=好きな文字列` | 書き込み (ファイルの書き込みと削除、再起動、キー入力) と、ファイルの読み出しに要るトークン。HTTP のヘッダ `X-Pix68k-Token:` で渡す |
| `syslog=192.168.1.2:514` | ログを UDP の syslog (RFC 5424) で送る先 (ポートを省くと 514) |
| `rs232c=tcp:2324` | X68000 の RS-232C を TCP の 2324 番で待ち受ける ([expansion.md](expansion.md) の「RS-232C (SCC のチャネル A)」を参照。`cmdline.txt` の `pix68k_rs232c` は読まない) |

`net_allow=` と `net_token=` のどちらも書かなければ、読むことだけができ、書き込みは断る。両方書けば、両方を満たしたときだけ書ける。

`net_token=` を書くと、ファイルを読む (`GET /files/...`) のにもトークンが要る。トークンは `pix68k.cfg` か `cmdline.txt` に書いてあり、
読めればそのまま書き込みと再起動に使えるため。その写し (`.new`、`.part`、`.old` や手で作った控え) もあるので、名前で選ばずに
ファイルはすべてトークンを求める。`/log`、`/thermal`、`/screen.ppm`、`/ts6bga.ppm`、`/screen2.ppm` はトークンなしで読める (`net_allow=` の制限は受ける)。

HTTP の口:

| 要求 | 内容 |
| --- | --- |
| `GET /` | 使い方の一覧と、syslog に送った行の数 |
| `GET /files/<パス>` | SD カード (起動したドライブ) のファイルを読む (`net_token=` があればトークンが要る)。`/` で終われば一覧 (1 行に `名前`、タブ、バイト数。ディレクトリは `名前/`) |
| `DELETE /files/<パス>` | ファイルを消す (トークンが要る。ディレクトリと、X68000 が使っているディスクのイメージは断る) |
| `PUT /files/<パス>`、`POST /files/<パス>` | ファイルを書く (トークンが要る)。`<パス>.part` に書き、受け取り終えたら `<パス>` と入れ替える (元のファイルは `<パス>.old` にしてから消す)。途中で切れたら元のファイルは変えない。大きさの上限はない (SD カードに 32KB ずつ書く)。`Content-Length` が要る (`Transfer-Encoding` は chunked でもほかでも断る、400) |
| `GET /log` | 起動してからのログ (UART と同じもの。最新の 64KB) |
| `GET /thermal` | 温度、ARM のクロック、ファームウェアがクロックを下げているか、ファン (Pi 5)。`名前=値` を 1 行ずつ返す (下に詳しく書いた) |
| `GET /screen.ppm` | X68000 の画面 (PPM)。X68000 が動いていれば、次に合成し終えたフレームを待って返す (下に詳しく書いた) |
| `GET /ts6bga.ppm` | TS-6BGA の仮想VRAM (PPM)。表示選択に関係なく、最新のスナップショットを元解像度・RGBで返す。ボード無効・未受信時は503 |
| `GET /screen2.ppm` | 第2 HDMI で選択中の映像ソース (PPM)。TS-6BGA 選択中はそのVRAM、通常時はフィルター前のX68000画面。HDMIへの拡大縮小・余白・OSDは含めない。ボード無効時は503 |
| `POST /reboot` | ディスクと SRAM を書いてから再起動する (トークンが要る。Ctrl + Alt + Delete と同じ手順。書けなければ断り、60 秒以内にもう一度頼むと書かずに再起動する) |
| `POST /reboot?profile=<名前>` | `/pix68k/pix68k-<名前>.cfg` の起動の組み合わせで再起動する (トークンが要る。手順は `POST /reboot` と同じ)。`pix68k.cfg` は書き換えない。次の起動はメニューを出さない。`profile=` が空なら組み合わせなし (`pix68k.cfg` だけ)。名前が正しくなければ 400、ファイルがなければ 404、`/pix68k/profile.sel` に書けなければ 500、起動したドライブがなければ 503 を返し、再起動しない。組み合わせのファイルの数が一覧の上限 (30) を超えていても、ファイルがあれば使う。起動時のメニューを出している間は、HTTP のサーバはまだ動いていない (メニューが終わってから待ち受ける)。受け付けたあとディスクを書き戻せずに再起動を断ったときは、`profile.sel` を前回の選択に戻す。戻せなかったときは、次の `profile=` なしの `POST /reboot` (Ctrl + Alt + Delete と設定メニューの Restart の前にも) でもう一度戻し、それでも戻せなければ 500 を返して再起動しない (SD カードに書けない間は、60 秒以内の 2 回目で書かずに再起動する手順も使えない)。選んだものは前回の選択 (`/pix68k/profile.sel`) にもなる ([README](../README.md) の「起動の組み合わせ」) |
| `POST /type` | リクエストの本体 (ボディ) の文字列を X68000 のキーとして打つ (トークンが要る。JIS 配列。押してから 40ms で離し、40ms 空けて次を打つ。`\n` は Enter、`\t` は TAB、`\b` は BS、`\e` は ESC。4096 バイトまで) |
| `POST /key?down=XX&mod=YY`、`POST /key?up=XX`、`POST /key?up` | USB キーボードの usage ID (16 進) でキーを押す / 離す / すべて離す (トークンが要る。`mod=` は USB の修飾キーのビット。01 左 Ctrl、02 左 Shift、04 左 Alt、08 左 GUI) |
| `POST /message?sec=N` | 本体の文字列 (UTF-8) を画面の左上に重ねて N 秒出す (トークンが要る。既定 10 秒、`sec=0` なら消すまで、上限 86400)。本体が空 (空白と改行だけ) なら消す。下に詳しく書いた |

```sh
# 例はどれも net_name= を書いていない (既定の名前 pix68k の) とき。net_name=x68000 なら http://x68000/ にする
# カーネルを入れ替えて再起動する (カーネルを置いた手元の機械から)
curl -H 'X-Pix68k-Token: 好きな文字列' -T kernel8.img http://pix68k/files/kernel8.img
curl -H 'X-Pix68k-Token: 好きな文字列' -X POST http://pix68k/reboot
# 起動の組み合わせ pix68k-gr2.cfg で再起動する
curl -H 'X-Pix68k-Token: 好きな文字列' -X POST 'http://pix68k/reboot?profile=gr2'
# 設定を読む / 書く
curl -H 'X-Pix68k-Token: 好きな文字列' http://pix68k/files/pix68k/pix68k.cfg
curl -H 'X-Pix68k-Token: 好きな文字列' --data-binary @pix68k.cfg http://pix68k/files/pix68k/pix68k.cfg
# ログ、温度、画面
curl http://pix68k/log
curl http://pix68k/thermal
curl -o screen.ppm http://pix68k/screen.ppm
curl -o ts6bga.ppm http://pix68k/ts6bga.ppm
curl -o screen2.ppm http://pix68k/screen2.ppm
# キー入力 (X68000 のリセット、CTRL + OPT.1 + DEL は Ctrl + GUI + Delete)
curl -H 'X-Pix68k-Token: 好きな文字列' --data 'dir\n' http://pix68k/type
curl -H 'X-Pix68k-Token: 好きな文字列' -X POST 'http://pix68k/key?down=4c&mod=09'
curl -H 'X-Pix68k-Token: 好きな文字列' -X POST 'http://pix68k/key?up'
# 画面の左上にメッセージを出す (30 秒) / 消す
curl -H 'X-Pix68k-Token: 好きな文字列' --data-binary '案1 OutRun\nいまの版' 'http://pix68k/message?sec=30'
curl -H 'X-Pix68k-Token: 好きな文字列' -X POST http://pix68k/message
```

curl の代わりに、この口を操作するコマンド `pix68kcli` (Go、macOS / Linux / Windows 向け) がある。宛先と token を設定ファイルに名前付きで書いておき、
`pix68kcli --host pi3 log -f`、`pix68kcli screen`、`pix68kcli files put kernel8.img /`、`pix68kcli reboot` のように使う。
作り方と使い方は [tools/pix68kcli/README.md](../tools/pix68kcli/README.md) にある。

`POST /message` のメッセージ (`src/platform/osd_message.h`):

- 1 行は半角 10 桁 (全角は 2 桁と数えるので 5 字) で、超えた字は次の行へ折り返す (入らない半角の空白は捨てるので、折り返した行の頭に空白は来ない。全角の空白は字として扱う)。
  行は 4 行まで。入りきらない分は字の切れ目で捨て、4 行目の終わりを「…」(全角。10 桁に収まるよう、要るだけ 4 行目の右の字を消す)
  にする。X68000 の画面 (Human68k の 1 行目など) に大きく重ならないよう、桁を少なくしてある。本体は 1024 バイトまで (超えれば 413)。
  `/type` と同じく `\n` で改行できる (`curl --data` は本体の改行を消すので、改行は `\n` か `--data-binary` で送る)
- 半角 (ASCII) は設定メニューと同じ 8x16 の字で出す。半角カタカナと全角 (JIS 第 1・第 2 水準と記号) は、X68000 の CGROM の字で出す
  (CGROM がなければ、全角は四角、半角カタカナは `?`。ただし「…」は点を 3 つ描く)。JIS X 0208 にない字 (丸数字、絵文字など) は四角
- 白い字に黒の背景で、右上の数字 (`osd=`) と同じく X68000 の画面をフレームバッファに写すところで重ねる。X68000 の画面の中身には
  書かないので、`/screen.ppm` には出ない。フレームバッファの高さが 900 ライン以上 (1080 ラインのモニタなど) なら 2 倍の大きさ。右上の数字と同じ行に並ぶときは、数字にかからない
  よう右を切る。設定メニューを開いている間は出さない
- 新しいメッセージは前のメッセージを置き換える。ログに `message: "案1 OutRun\nいまの版" (30 s)` の 1 行を残す (改行は `\n`、
  ほかの制御文字は `?` にする。160 バイトを超えれば切る)
- 消す時刻は Pi を起動してからの時計で数える。カーネルを入れ替えて再起動すると消える
- ホスト版は `--message TEXT` (`--message-sec N`) で、同じものをウィンドウの左上に出せる (折り返しと「…」も同じ。HTTP の口はない)

- X68000 につないでいるディスクのイメージ (`fd0=` などで指定したファイル) は書き換えと削除を断る (409)。書くときに使う `<パス>.part` と
  `<パス>.old` がそのイメージに当たる場合も断る。名前は、続いた `/` や大文字と小文字の違い、短い名前 (`HUMAN~1.XDF`) をそろえてから比べる
  (FatFs でディレクトリエントリの長い名前を引く)。設定メニューを開いている間の書き込みも断る (503)。受け取っている間にメニューを
  開いたり、メニューでそのファイルをつないだりした場合は、入れ替える直前にもう一度見て、受け取った内容を捨てる (503 / 409)。
  SD カードを読めず、使っているイメージと同じファイルか決められないときも断る (503)
- 設定メニューのフロッピーディスクの一覧には、名前が `.new`、`.part`、`.old` で終わるファイル (置き換えの一時ファイル) を出さず、つなぐこともしない
- 要求の頭は厳しく読む。ヘッダ名にトークンの文字以外 (コロンの前の空白など) があるもの、NUL などの制御文字 (HTAB 以外) があるもの、
  `Content-Length` の値が数字でないか重なって違うもの、`Transfer-Encoding` があるものは 400
- TCP/IP、HTTP、syslog と SD カードの読み書きはコア 0 で行う。そのタスクを動かす間は、要求がないときも、画面を写す役をコア 2
  (合成するコア) に任せる (USB を探す間と同じ)。USB の Ethernet (Raspberry Pi 3 Model B+ の LAN7800 など) は、受信を見るたびに USB の転送が
  終わるまで待つため。X68000 (コア 1)、画面の合成、音は止めない。
  コア 0 が写せずに表示されなかったフレームの数は、10 秒ごとのログの `replaced before shown` で見られる
- `/thermal` が返す行 (トークンなしで読める):
  - `temp_c=52.3`: SoC の温度 (要求のたびに読む。読めなければ `?`)
  - `clock_set_mhz=2400`、`clock_measured_mhz=2400`: ARM のクロックの要求した値と実測の値
  - `throttled=0`: `PROPTAG_GET_THROTTLED` の値 (16 進。bit0 電圧不足、bit1 クロックの上限を下げている、bit2 クロックを下げている、
    bit3 温度の上限に達している。bit16-19 は、その前の報告からの間に同じことが起きたか)
  - `throttled_since_boot=50005`: 起動してから読んだ `throttled` をすべて OR した値 (0 なら、一度も下げていない)
  - `report_age_s=3`: クロックと `throttled` を読んでからの秒数。この 2 つはログの `cpu:` の行を出すとき
    (X68000 を動かしている間の 10 秒ごと) に読んだ値で、まだ読んでいなければ `clock_set_mhz` からここまでの行は出ない
  - `fan=pwm` (Pi 5 だけ。`onoff` は PWM が使えず回すか止めるかだけ、`none` は触っていない)、`fan_level=1` (段階 0 から 4)、
    `fan_duty=75` (速さ。255 が全開)、`fan_rpm=2890` (RP1 が測った回転数)
  - `mem_total_kb=`: メモリ全体。`heap_low_kb=`、`heap_low_unused_kb=`: 1GB より下のヒープの大きさと、その中で一度も使っていない部分。
    `heap_high_kb=`、`heap_high_unused_kb=`: 1GB より上のヒープ (Pi 4 / Pi 5 でメモリが 1GB より多いときだけ)。
    解放したブロックは使い回すだけで `*_unused` には戻らない ([baremetal.md](baremetal.md) の `cpu:` の行の説明を参照)
- `/screen.ppm` が返す画面: 上のとおり、HTTP のタスクを動かす間は画面を写す役をコア 2 に任せており、その間に合成したフレームは
  コア 0 に渡らない。そこで、要求を受けたら写す役を一度コア 0 に戻し、フレームを受け取って HDMI に写してから、それを返す
  (返したあと、またコア 2 に任せる)。受け取るのは、ふつうは役を戻したあとに次に合成し終えたフレームで、
  コア 2 に任せる前からコア 0 に渡されたまま残っているフレームがあれば (それが最新なら) すぐにそれを受け取る。
  - フレームを待つのは、待った時間の合計で長くて 200ms。来なければ、最後にコア 0 が受け取ったフレームを返す (古いことがある)。
    このときはログに `screen: no new frame in 200 ms` の警告を出す。続けて頼まれても 10 秒に 1 回だけ出し、出さなかった回数を次の警告に添える
  - 200ms には次の時間を数えない。役を戻すときにコア 2 がフレームを HDMI に写している途中なら、写し終えるまで待つ時間
    (ふつうは 1 フレーム、残っていたフレームを先に写していれば 2 フレームを写す時間)。受け取ったフレームを HDMI に写す時間と、
    下の SD カードの読み書きの時間も数えない。そのため、要求から返すまでの時間は 200ms より長くなることがある
  - 大きなハードディスクのイメージのチャンクの読み込み (コア 0 が SD カードから読む) をコア 1 が待っていると、読み込むまでフレームが来ない。
    そのため、SD カードの読み書きが残っていれば、40ms 待ってもフレームが来ないたびに、役をコア 2 に任せてから読み書きし、また待つ
  - X68000 を止めていて設定メニューを開いていないとき (再起動の前の書き戻しなど) は、待たずに最後に合成し終えたフレームを返す
    (コア 2 が自分で写してコア 0 に渡らなかったものでも)。HDMI には写さない。コア 2 が自分で写したフレームは、
    コア 2 が次のフレームを描くのと同じバッファにあり、X68000 は次のフレームの表示期間に入ったところで止まるので、
    頭の数ラスタが次のフレームのもので上書きされていることがある
  - 設定メニューを開いている間は、メニューの下に描いているフレームを返す。メニューは写らない
- 同時に受け付ける接続は 1 つ。要求の頭は全体で 10 秒、`/type` などの小さな本体も全体で 10 秒まで。ファイルの本体は、10 秒ごとに 4KB 届かなければ切る (SD カードに書いている時間は 10 秒に数えない)
- `Host:` ヘッダが Pi のアドレス (`192.168.1.50` など) か `net_name=` の名前 (既定は `pix68k`。後ろに `:80` が付いてもよい) でなければ、GET も含めて断る (403)。
  ほかのドメインの名前を Pi のアドレスに向けて (DNS リバインディング)、ブラウザのページから読み書きさせないため。
  `curl http://192.168.1.50/` と、`net_name=` を書いていなければ `curl http://pix68k/` が通る。ルータが付けるドメイン付きの名前 (`pix68k.lan` など) は断るので、アドレスか `net_name=` の名前で送る。
  `Host:` のない HTTP/1.0 の要求は受ける
- `Origin:` ヘッダの付いた書き込み (ブラウザのページから送られたもの) は断る (403)。`net_allow=` だけでトークンなしの設定でも、ほかのサイトのページから書き込みや再起動をさせないため
- PUT / POST の送り先が既存のディレクトリなら断る (400)。`/files/pix68k` のようにファイル名を書き忘れて、ディレクトリを置き換えないように
- X68000 が使っているディスクのイメージも GET で読めるが、書き戻しと重なると中身が揃わないことがある
- `pix68k.cfg` の読めない値をログに出すとき、`net_token=` の値は出さない (`/log` はトークンなしで読めるため)。
  ほかの読めない行 (項目の名前を打ち間違えたものなど) は、そのままログに出るので `/log` から読める。トークンを書いた行は名前を打ち間違えないこと
- ネットワークは USB を探したあとに動かし始める (起動にかかる時間は変わらない)。アドレスが決まると `net: address 192.168.1.50` をログに出す
- キー入力は、USB キーボードと同じく、すべてのキーボードと合わせてから X68000 に送る (仮想のキーボードとして 1 枠を使う)。Ctrl + Alt + Delete を送ると Pi を再起動する
- syslog には UART と同じ行を送る (`/log` と同じリングから読む)。送った行の数と失敗した数は `GET /` の最後に出る。最初の 1 行を送れたら `net: syslog: sending to ...`、送れなければ `net: syslog: cannot send (...)` をログに出す
- 認証は簡単なもの (平文のトークンと相手のアドレス) なので、家の中のネットワークだけで使う
- Neptune-X (`neptune=on`) で Ethernet を使うとき (`neptune_link=eth`) は、ネットワークの口は動かさない (ログに警告を出す)。
  どちらも同じ Ethernet のデバイスを使うため。宛先の MAC アドレスで振り分けて両方を動かす作りは、まだない
- QEMU 用のビルド (`tools/build_baremetal.sh 3 --qemu`) では、Circle の DWHCI (Pi 3 の USB ホストコントローラ) のドライバを書き換えて、
  `-device usb-net` からフレームを受け取れるようにしている。QEMU の DWC2 は、データが届いて転送が終わったときも割り込みの状態 (HCINT) の NAK のビットを消さないので、
  そのままでは受け取った長さが 0 になる。Circle の `USE_NAK_USB_FIX` で避けると、こんどは QEMU が止めたチャネルでフレームを受け取って
  捨ててしまい、HTTP の要求がほとんど届かない (#117)。実機のビルドは書き換えない
- QEMU 用のビルドでは、Circle の UDP の接続 (`lib/net/udpconnection.cpp`) も書き換えて、閉じた接続が届いたパケットを受け取らないようにしている。
  Circle の DHCP は、ポート 68 の接続を閉じて作り直してから DISCOVER を送るが、閉じた接続は次の処理の回まで一覧に残る。QEMU は OFFER を
  すぐ返すので、その残った接続が OFFER を捨ててしまい、4 秒後の送り直しでやっとアドレスが決まっていた (`dhcp: No response from server. Retrying.`。#136)。
  DHCP サーバの答えが速ければ実機でも起きうるが、確かめていないので、実機のビルドは書き換えない
